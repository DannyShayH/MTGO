Reviewed on 11 November 2026 for issue #10. The team intends to follow the [Restaurant-Delivery Marketplace recipe](https://docs.medusajs.com/resources/recipes/marketplace/examples/restaurant-delivery), adapting it to the agreed MTOGO business. This review records source evidence and checks to carry into each Feature grill; it does not choose each Feature's implementation.

## Versions and evidence

The [example package manifest](https://github.com/medusajs/examples/blob/aae76657952903750dfcaaaf28b6746f20ab1af5/restaurant-marketplace/package.json) pins Medusa packages to 2.14.0. The installed backend Framework and Medusa packages are 2.22.4. The example snapshot is pinned to upstream commit `aae76657952903750dfcaaaf28b6746f20ab1af5` so later upstream changes do not silently change this review.

The comparison used installed package documentation in `apps/backend/node_modules/@medusajs/{framework,medusa,core-flows,order,payment}/AGENTS.md`, plus the installed Framework's HTTP declarations and exports. This is a static comparison; the example has not been compiled or exercised as an application against this repository.

## Findings for later Feature grills

| Area                             | Observed source behavior                                                                                                                                                                                                                                                                                                                                                                                                                      | MTOGO boundary or required verification                                                                                                                                                                                                   |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Order creation and preparation   | The [handling workflow](https://github.com/medusajs/examples/blob/aae76657952903750dfcaaaf28b6746f20ab1af5/restaurant-marketplace/src/workflows/delivery/workflows/handle-delivery.ts) waits for an agent claim before creating the Order, then waits for preparation to start.                                                                                                                                                               | Agreed MTOGO behavior places the paid Order before Restaurant acceptance or assignment; preparation and assignment proceed independently after acceptance.                                                                                |
| Commerce mutations               | The example's [Order step](https://github.com/medusajs/examples/blob/aae76657952903750dfcaaaf28b6746f20ab1af5/restaurant-marketplace/src/workflows/delivery/steps/create-order.ts) calls `createOrders` directly, and its [fulfilment step](https://github.com/medusajs/examples/blob/aae76657952903750dfcaaaf28b6746f20ab1af5/restaurant-marketplace/src/workflows/delivery/steps/create-fulfillment.ts) calls `createFulfillment` directly. | Installed Order and core-flows documentation recommends commerce workflows, and repository rules require them to preserve links, events and other commerce side effects. Adaptation must verify payment, refunds and fulfilment together. |
| Fulfilment location              | The fulfilment step hardcodes `location_id: "1"`.                                                                                                                                                                                                                                                                                                                                                                                             | The Feature must resolve an actual configured location; this example value does not establish valid Restaurant pickup behavior here.                                                                                                      |
| HTTP validation and imports      | The [store route](https://github.com/medusajs/examples/blob/aae76657952903750dfcaaaf28b6746f20ab1af5/restaurant-marketplace/src/api/store/deliveries/route.ts) imports HTTP types from the Framework root and parses its body inside the handler.                                                                                                                                                                                             | The installed root still re-exports HTTP types, so this is not evidence of a removed API. Installed docs recommend the `/http` subpath, and project patterns put body validation in middleware with typed validated input.                |
| Middleware verbs                 | The example uses `method`; installed Framework declarations accept both `method` and `methods`.                                                                                                                                                                                                                                                                                                                                               | A spelling difference alone is not a compatibility failure.                                                                                                                                                                               |
| Competing claims                 | The [claim workflow](https://github.com/medusajs/examples/blob/aae76657952903750dfcaaaf28b6746f20ab1af5/restaurant-marketplace/src/workflows/delivery/workflows/claim-delivery.ts) updates the agent and status, then signals workflow progress.                                                                                                                                                                                              | This source inspection does not prove atomic ownership or the one-active-delivery rule. The delivery Feature must verify simultaneous claims, retries and recovery against MTOGO's guarantees.                                            |
| Commercial and operational scope | The recipe introduces Restaurant and Delivery concepts and a tracked delivery journey.                                                                                                                                                                                                                                                                                                                                                        | MTOGO additionally needs its agreed fees, failure responsibility, bonus pool and points, three feedback subjects, role boundaries and website timeline. Existing recipe behavior does not decide these rules.                             |

Keep the installed dependency versions. Each Feature grill chooses the concrete adaptation, checks the installed package APIs and verifies the agreed behavior. The [domain model](/MTGO/product/domain-model/) and ADRs hold business decisions.
